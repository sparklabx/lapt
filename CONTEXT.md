# lapt

A local, rootless installer that wraps `apt-get download` + `dpkg -x` to put Debian/Ubuntu packages under `$HOME/.local` without sudo and without writing to the system package database. Read-only queries against it (e.g. `dpkg -s`, `dpkg --compare-versions`) are fine.

## Language

**Closure**:
The transitive Depends+PreDepends set of a package, resolved via `apt-cache depends --recurse` (Recommends/Suggests/Conflicts/Breaks/Replaces/Enhances excluded). Ignores Conflicts/Breaks metadata entirely — collision detection at assemble/vendor time is the only safety net for what apt's Conflicts field would otherwise have prevented.
_Avoid_: dependency tree, dependency graph (no parent/child structure is ever built — the closure is a flat set)

**OR-alternative** (closure member):
A closure member that apt expressed as multiple alternatives (`A | B | C` — in `apt-cache depends --recurse` output, consecutive lines where all but the last of a run are prefixed `|Depends:`/`|PreDepends:`). `resolve_closure` preserves the whole alternative list as one closure member rather than collapsing it to a single package name; which one (if any) is actually fetched and bundled is decided later, entirely by the any-of rule in **System-satisfied dependency** (below) — never inside `resolve_closure` itself. This keeps `resolve_closure` apt-only and deterministic: no `dpkg` call happens there, and a fixed alternative-group list is what a fixture-based test asserts, regardless of what's installed on the machine running the test. See ADR-0010.
_Avoid_: picking a single alternative during closure resolution (would smuggle a `dpkg` dependency into what must stay a pure, fixture-testable parser)

**Top-level package**:
The package name given directly to `install`, `fetch`, or `vendor` — as opposed to a package that only appears because something else's closure depends on it.
_Avoid_: root package

**Scope-restricted package**:
A package whose closure member has every file under `usr/**`. Checked via `dpkg-deb -c` before extraction; any closure member failing this check hard-aborts the whole operation. This invariant is what makes it safe to never run maintainer scripts, and what makes flattening (below) unambiguous.
_Avoid_: usr-only package (fine as shorthand in prose, but the glossary term is this one)

**`LAPT_HOME`**:
The one root directory lapt owns end to end — `opt/`, `cache/`, and (see **Exposure**, below) the top-level package's own `bin/` and `share/man/`. Always `$HOME/.lapt`, not configurable — there's exactly one location to look at, back up, or wipe. Superseded the earlier independent `LAPT_OPT_ROOT`/`LAPT_CACHE_ROOT` overrides. `lapt init` writes `$LAPT_HOME/env` (prepending `$LAPT_HOME/bin` to `PATH` and `$LAPT_HOME/share/man` to `MANPATH`, each guarded so re-sourcing it doesn't duplicate the entry) and tells the user to source it from their shell rc — never writes to the rc file itself. See ADR-0011.
_Avoid_: `LAPT_OPT_ROOT`, `LAPT_CACHE_ROOT` (retired env vars, both now just `$LAPT_HOME/opt` and `$LAPT_HOME/cache`); treating `LAPT_HOME` as an overridable env var (it's read internally but always set to `$HOME/.lapt`, ignoring anything pre-set in the environment)

**Cache entry**:
The extracted, verbatim (`usr/`-prefixed) content of one downloaded `.deb`, stored once at `$LAPT_HOME/cache/<name>_<version>/`. Immutable once written — never re-extracted for a given name+version. Not evicted automatically, and not an LRU cache; only removed by an explicit `lapt prune`, which reclaims entries no longer referenced by any assembled or vendored package (see ADR-0006 — checked via hardlink count, no manifest needed since consumption is always by hardlinking).
_Avoid_: package store

**Flattening**:
The path rewrite applied when consuming a cache entry (during assemble or vendor, never when populating the cache itself): the leading `usr/` is stripped, and a multiarch triplet directory (e.g. `x86_64-linux-gnu`) directly under `lib/`, `include/`, or `pkgconfig/` is stripped too. Cache entries themselves keep the verbatim Debian layout; only the assembled/vendored copy is flat.

**Assemble**:
What `lapt install <pkg>` does, once two early-exit checks pass: `opt/<pkg>` already existing (no-op, "already installed — run `remove` first") and `<pkg>` already being installed by the system package manager (no-op notice and exit, nothing created or tracked — ADR-0007; distinct from a **system-satisfied dependency**, below, which only skips bundling that one dependency and keeps assembling the rest). Past those: for every closure member other than the top-level package checks whether it's a **system-satisfied dependency** (below) and skips it if so, hardlinks the rest of each closure member's cache entry into one flattened `opt/<pkg>/` tree (rewriting `.pc` files unconditionally, same as **Vendor**'s rewrite below — a no-op sed pass for a package with none), generates a `.wrap` wrapper where a runtime `lib/` exists or the closure has `bin/` files from a package other than the top-level one, performs exposure for the top-level package's own `bin`/`man` entries (nothing to expose for a library-only package, which is fine — it's still a tracked, listed, removable `opt/<pkg>`), writes `.lapt/version`. No requirement that the top-level package have any `usr/bin` of its own — a library-only package (e.g. a `-dev` package) assembles the same way any other does. See ADR-0012 (supersedes ADR-0005, which used to hard-abort this case).
_Avoid_: vendor, vendoring (reserved below for the unrelated `vendor` subcommand)

**System-satisfied dependency**:
A closure member that's skipped — fetched and bundled by neither `assemble` nor `vendor` — because the host already has it installed: checked by package name via read-only `dpkg -s` only, never by probing `/usr/lib` or `$PATH` (a same-named file there doesn't prove it's the right package). No version comparison is performed — presence in `dpkg` is the whole check. There is no per-edge version constraint available to compare against (`resolve_closure`'s flat closure model discards it, and even `apt-cache depends --recurse` never emits one, verified live), and Debian's package-naming convention means an ABI break forces a new package name, so any installed version under a given name is already link-compatible. This can still be wrong for the minority of edges that carry a real version floor (e.g. `libgssapi-krb5-2 (>= 1.17)`) — accepted as a known limitation, see ADR-0007. For an **OR-alternative** group specifically, the group counts as satisfied if *any* alternative in it is installed — verified against real apt behavior (`apt-get install --print-uris -s` on a package whose closure includes `debconf (>= 0.5) | debconf-2.0` skips fetching either half once `debconf` is already installed). Only when none of a group's alternatives is system-satisfied does one get picked concretely to fetch and bundle — deterministically, the first alternative with an `apt-cache` candidate, with no host state involved in that pick. Either way, a group is never itself recorded or bundled — only the one concrete name that ended up satisfied-and-skipped, or picked-and-bundled, ever reaches `.lapt/system-deps` or `bundle_manifest`. See ADR-0010. Only a non-top-level closure member is ever eligible — the top-level package is always bundled; this now applies uniformly, since `vendor` no longer resolves a closure of its own (see **Vendor**, below) and every package it names is really `assemble`'s top-level package for its own install. Skips are recorded to `.lapt/system-deps` (one `<name> <version-relied-on>` per line, same flat-file style as `.lapt/version`) so `lapt fix` can re-verify them later; this is the one deliberate, scoped exception to frozen-private (below) — a skipped dependency can go stale if the host's package manager later changes it, until `fix` re-bundles it. See ADR-0007.
_Avoid_: checking for a same-named file/binary on disk or `$PATH` (unreliable — doesn't verify package identity or version)

**`lapt fix <pkg>`**:
Re-verifies every entry in a package's `.lapt/system-deps` against current `dpkg` state; anything no longer installed is fetched and bundled into `opt/<pkg>/` now (a partial re-assemble, regenerating the `.wrap` wrapper if bundling newly triggers one). The only way staleness gets repaired — `lapt list` does not proactively check this, and `install` on an already-installed package stays a plain no-op. See ADR-0007.

**Exposure**:
Symlinking the top-level package's own executables (`bin/`) and `man` pages (`share/man/`) out of `opt/<pkg>/` into **`LAPT_HOME`** (above) — self-contained, reachable only once the user sources `LAPT_HOME/env` (see `lapt init`). No other category is exposed anywhere: bash-completion scripts and `.desktop`/icon/MIME entries are simply never symlinked out of `opt/<pkg>/`, a real reduction from ADR-0004's original scope, not a relocation of them. Scoped to the top-level package's own files only — never to files contributed by a dependency in the closure, which stay hardlinked inside `opt/<pkg>/` (reachable *from inside* the `.wrap` wrapper via a `PATH` prepend, just not exposed to the shell). Every exposed path is recorded to that package's **exposure list** (below). No desktop/mime/icon cache-refresh commands are run — files are placed and left. See ADR-0004 (superseded by ADR-0011), ADR-0011.
_Avoid_: exposing everything under `opt/<pkg>/**` (would leak incidental dependencies like a bundled `python3` into the shared dir, and create ownership conflicts between unrelated installs that share a dependency); bin exposure / man exposure as separate concepts (one mechanism, same scoping, same removal path, one destination root)

**Exposure list** (`.lapt/exposed`):
A flat, one-relative-path-per-line file (relative to `LAPT_HOME`) written by `assemble` alongside `.lapt/version`, recording every symlink created by exposure for that package. `remove` reads it directly to know what to unlink — O(this package's own exposure count), not a scan of the shared dir (rejected: O(everything ever exposed)). Scoped to and deleted with its `opt/<pkg>/`; not a global manifest (ADR-0002 still holds). See ADR-0004, ADR-0011.

**Vendor**:
What `lapt vendor <pkg...>` does: requires every named package to already be `assemble`d (`opt/<pkg>/.lapt/version` exists) — if any aren't, reports all the missing names together in one error, nothing printed to stdout, nonzero exit. Otherwise prints an env script to stdout (no file written anywhere) with `PATH`, `LD_LIBRARY_PATH`, `PKG_CONFIG_PATH` lines pointing at each named package's own `opt/<pkg>/{bin,lib,lib/pkgconfig}`, in the order given on the command line, for the caller to redirect or source (e.g. `. <(lapt vendor libevent-dev libncurses-dev)`) — typically to build something else against an already-installed library-only package without polluting the system prefix. Does no fetching, no closure resolution, no `dpkg` checks, and no `.pc` rewriting of its own — all of that already happened once, at each package's own `assemble` time (`.pc` rewriting is now unconditional there, see **Assemble**, above). Never touches `opt/`, creates no state of its own; purely reads what `assemble` already produced. See ADR-0012, ADR-0013.
_Avoid_: resolving a closure or fetching anything (that's `assemble`'s job now, not vendor's — see ADR-0013); a shared `target-dir` merging multiple packages' files together (retired — each named package keeps its own separate `opt/<pkg>`, chained together only via the env script's `PATH`-style prepends)

**`lapt wrap <binary> <target-dir>`**:
Moves an arbitrary, already-built binary that is not an apt package (e.g. a self-built Go binary needing a C library) into `<target-dir>/bin/<name>`, generates a `.wrap`-style wrapper alongside it that prepends `<target-dir>/lib` to `LD_LIBRARY_PATH` before exec'ing the moved binary, then symlinks `$LAPT_HOME/bin/<name>` to that wrapper — reusing **Exposure** unchanged, just pointed at `<target-dir>` instead of an `opt/<pkg>` tree. `<target-dir>` is expected to be a **Vendor** target-dir, already or about to be populated with whatever runtime libraries the binary needs. Never prepends to `PATH` the way `assemble`'s wrapper sometimes does — `vendor` never populates `target-dir/bin` with dependency binaries, so there is never another `bin/` to reach. No tracked state, no removal subcommand, same as `vendor`: undo by hand (`rm` the symlink, optionally the moved binary).
_Avoid_: install, assemble (no apt closure is ever resolved here, no `.lapt/version` is ever written — the input is a binary path, not a package name)

**Frozen-private**:
The policy that runtime libraries are never shared between installed packages — each `opt/<pkg>` gets its own complete, self-sufficient copy of every closure member's `lib/`, sized at assemble time and never updated by a later, unrelated install. No shared mutable lib pool, no reference counting. One deliberate, scoped exception: a **system-satisfied dependency** (above) is never bundled at all, so it can drift with the host until `lapt fix` re-bundles it — everything actually bundled, including the top-level package always, remains exactly as frozen as stated here.
_Avoid_: vendoring in the LD_LIBRARY_PATH sense (unrelated to the `vendor` subcommand)
